DO EVENTS RAISE PRICES?

[ ] Home [*] Research Methods

Research question

Higher demand often means higher prices. Given that entertainment events like for example concerts cause an influx of visitors to the location, it is not unreasonable to assume that the short-term rent prices will increase as the date of the show approaches. We decided to test this hypothesis in our "Events and Rents" project.

Data Collection

Location Data

Each city was first converted into geographic coordinates using Nominatim, an open-source geocoding service based on OpenStreetMap data.

Using coordinates rather than only city names makes the event search more precise, especially for large metropolitan areas where relevant venues may lie outside the administrative boundaries of the city itself.

Event Data

Event information was collected from MusicBrainz, an open collaborative music database. Since the MusicBrainz API does not directly support searching for events within a geographic radius, we used a two-step workaround:

  1. Find events in the broader area
    Search for events associated with the target city or region and within the requested date range.
  2. Filter by venue distance
    Retrieve the coordinates of each event venue, calculate the distance from the target location, and keep only events within the chosen radius (50 km default).

This approach reduces irrelevant results while still capturing events in venues that belong functionally to a metropolitan area but are located outside its strict administrative boundaries.

Airbnb Data

Historical Airbnb data was obtained from Inside Airbnb – a non-profit "...mission driven project that provides data and advocacy about Airbnb's impact on residential communities", which publishes periodic snapshots containing information about listings, prices, availability, room types, and locations.

Unfortunately, only two last snapshots per city were accessible directly from the website. However, we discovered, that altering the date in the URL might yield an earlier snapshot.

Example: a known URL of a snapshot for New-York City for 2026-02-13.

https://data.insideairbnb.com/united-states/ny/new-york-city/2026-02-13/data/listings.csv.gz

Turn it into a template:

https://data.insideairbnb.com/united-states/ny/new-york-city/{}/data/listings.csv.gz

Try another date (this one actually exists):

https://data.insideairbnb.com/united-states/ny/new-york-city/2025-12-04/data/listings.csv.gz

Because snapshots are published periodically rather than daily, an event date does not necessarily have a snapshot recorded on exactly the same day. Events were therefore grouped by city and month and matched to the nearest available Airbnb snapshot within the surrounding time window.

If available, snapshots before and after the matched snapshot were also identified. This provides additional temporal context and makes it possible to compare changes in the local Airbnb market over time rather than relying on a single observation.

The required snapshot files were then downloaded and stored for further processing.

Optimisation

To avoid rate limiting or potentially being mistaken for a DDoS attack, in snapshot search, event search and snapshot download stages the workload was split into a couple of docker containers, each connected to a different VPN server which allowed to have more IPs and to circumvent rate limiting (especially in the MusicBrainz case, which allows only 1 request per second). In the containers, the workload was split up further into asynchronous workers to speed up the process.

Data Cleaning and Preparation

The raw Inside Airbnb data is distributed across several datasets. In particular, listing-level and calendar-level information had to be combined before analysis.

The datasets were joined using the listing identifier, producing observations at the level of one Airbnb listing x one calendar date.

Price values were converted from formatted currency strings into numeric values. When several price fields were available, a fallback strategy was used to select the most appropriate valid price.

Rows without essential information (city, date, price and location information) were removed.

Data Analysis

After cleaning, the data was aggregated by calendar date to describe daily changes in the Airbnb market.

Metrics:

·       Median price as the main measure of the typical nightly price.
·       Mean price as an additional reference measure.
·       25th and 75th price percentiles (IQR) to represent the spread of prices.
·       Number of listings observed on that date.
·       Number of available listings to describe changes in booking availability.

The median was used as the primary price indicator because Airbnb prices are typically right-skewed: a relatively small number of very expensive properties can strongly influence the arithmetic mean.

To distinguish event-related changes from normal short-term price variation, we also calculated a 30-day rolling median baseline based only on previous observations.

Price change relative to baseline =
(daily median price − rolling baseline) / rolling baseline

The rolling baseline is shifted by one day, meaning that the price observed on a given date does not contribute to its own baseline. This avoids artificially reducing or inflating the measured deviation.

A positive deviation around an event date indicates that accommodation prices were higher than their recent local baseline. Availability was analysed alongside prices as an additional indicator of demand: decreasing availability may indicate that listings are being booked as the event approaches.


        metrics = panel.groupby("date").agg(
            median_price=("price", "median"),
            mean_price=("price", "mean"),
            p25_price=("price", lambda s: s.quantile(0.25)),
            p75_price=("price", lambda s: s.quantile(0.75)),
            n_listings=("price", "count"),
            n_available=("available", lambda s: (s == "t").sum()),
        ).reset_index()
          
        metrics["rolling_baseline_median"] = (
            metrics["median_price"].rolling(rolling_days, min_periods=1).median().shift(1)
        )

        metrics["pct_vs_baseline"] = (
            metrics["median_price"] - metrics["rolling_baseline_median"]
        ) / metrics["rolling_baseline_median"]

        metrics["availability_rate"] = metrics["n_available"] / metrics["n_listings"] * 100

Detailed metric explanation:

Metric Meaning
median_price Median nightly price across all listings observed that day. Used as the primary series because nightly rental prices are right-skewed and a few very expensive listings would inflate a plain mean.
mean_price Mean nightly price, plotted alongside the median for comparison.
p25_price / p75_price 25th/75th percentile price (interquartile range), drawn as a shaded band around the median to show the spread of prices, not just its center.
n_listings Number of priced listings observed that date (sample size).
n_available Number of those listings still marked bookable (available == "t").
availability_rate n_available / n_listings * 100 — the percentage of listings still available. A scarcity/demand proxy: falling availability near an event date suggests bookings are filling up.
rolling_baseline_median A 30-day trailing rolling median of median_price, shifted by one day so a day's own price never contributes to its own baseline (avoids self-referential inflation).
pct_vs_baseline (median_price - rolling_baseline_median) / rolling_baseline_median — percentage deviation of a day's price from its own recent trailing baseline. This is the "event price lift" signal: a spike here around an event date suggests event-driven demand.

Visualization

The processed data was visualized as interactive time-series plots.

The main price visualization combines:

  • daily median price,
  • rolling baseline median
  • daily mean price,
  • the interquartile range (25th–75th percentile),
  • and vertical markers indicating event dates.

A separate visualization shows the percentage of Airbnb listings that remained available over time, using the same event markers.

Displaying event dates directly on the price and availability timelines makes it possible to visually examine whether unusual changes occur shortly before, during, or after major local events.

Pipeline Overview

City → Coordinates → Event Search → Airbnb Snapshot Matching → Download → Data Cleaning → Filtering → Analysis → Visualization

This workflow allows event and accommodation data from different sources and time scales to be transformed into a consistent daily dataset that can be used to investigate whether local events coincide with changes in Airbnb prices and availability.
